# Gmail sales inbox

The dashboard connects one Gmail mailbox per authorized dashboard user. Sales → Gmail Sales Inbox opens matching conversations and their files, searches imported messages, and links conversations to quotations and orders. Mail and links are private to the connecting dashboard account. Creating a sales document from an email produces a draft for review.

## Server setup

1. Enable the **Gmail API** in the Google Cloud project for the OAuth client. The existing `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are used by default. Alternatively set dedicated `GMAIL_CLIENT_ID` and `GMAIL_CLIENT_SECRET` values.
2. In the Google Auth Platform / OAuth consent screen, allow `https://www.googleapis.com/auth/gmail.readonly`. If the app is in Testing, add the receiving Gmail account as a test user. External apps using this restricted scope may require Google verification for production. Testing refresh tokens normally expire after seven days for Gmail scopes.
3. Add the exact authorized redirect URI to the **Web application** OAuth client:
   - Production: `https://www.explosionproofelectrical.com/api/gmail/callback`
   - Local development: `http://localhost:3000/api/gmail/callback`
   - If using another hostname, register `<BETTER_AUTH_URL origin>/api/gmail/callback` instead. The initiating dashboard and callback must use the same origin.
4. Set `BETTER_AUTH_URL` to the actual site origin. Set `GMAIL_TOKEN_ENCRYPTION_KEY` to a base64-encoded 32-byte random key. Generate it using a password manager or a cryptographically secure generator. Keep it stable and secret, back it up, and use separate keys per environment. Changing it requires reconnecting Gmail. Never use a `NEXT_PUBLIC_` variable for credentials.
5. Apply the additive database migration with `pnpm exec prisma migrate deploy`, then regenerate/build with `pnpm build`. Existing migrations must be reviewed before deploying; do not reset the database.
6. Sign in to an allowed dashboard account, open `/dashboard/inbox`, click **Connect Gmail**, select the mailbox that receives orders/inquiries, and allow read access.
7. Add a randomly generated production `CRON_SECRET` (at least 32 characters) to this exact Vercel project, then deploy. `vercel.json` schedules `/api/cron/gmail` every five minutes; Vercel supplies `Authorization: Bearer <CRON_SECRET>`. The route rejects missing/incorrect credentials. The current Pro project supports this interval. Check the production cron execution logs after deployment. Preview deployments do not run the schedule. Keep this secret server-only.
8. For PDF item extraction, set `ORDER_PDF_AI_MODEL` to a file-input/structured-output model available to the team's AI Gateway account. The deployed configuration was checked with `google/gemini-2.5-flash`. Vercel deployments authenticate using their automatically supplied `VERCEL_OIDC_TOKEN`. Local scripts must explicitly load an uncommitted environment file containing a valid pulled OIDC token, or use an AI Gateway key. A supported model and available credits are required. Do not purchase credits or enable automatic top-ups without the account owner's approval.

The Codex Gmail connector does not grant this independently hosted website OAuth credentials. The mailbox owner must complete the site's Google consent flow.

## Behavior

- The default Gmail query matches inbox emails with order, purchase order, inquiry, enquiry, RFQ, quotation or quote request in the subject. Edit the query on the inbox page to match the business's actual subjects or labels. For example, `in:inbox label:Sales` or `in:inbox {subject:order subject:enquiry}`. This is keyword/search filtering, not automatic intent classification.
- The first sync checks the last 30 days. Later syncs use the last successful checkpoint with a two-minute overlap and deduplicate by Gmail message ID. Pagination is followed up to 1,000 matches; exceeding this shows an error and preserves the checkpoint. Narrow the filter to continue.
- The production cron fetches mail every five minutes once `CRON_SECRET` is configured and the schedule deployed. The dashboard also checks once a minute while visible and when focus returns. The next successful sync catches up since its checkpoint. Background fetching imports mail; browser alerts/toasts appear when the dashboard is open. This does not send email or mobile push notifications.
- Sync skips bodies already imported and fetches at most 30 new messages plus 10 older bodies per minute, leaving Gmail quota for reading and files. Large initial imports continue across checks without advancing their search checkpoint until complete. Google quota errors are distinguished from expired access; the reader falls back to the privately cached message text while the quota resets.
- The initial sync populates the bell and inbox. New matches found during subsequent checks show a toast. The bell summarizes the latest 100 emails; the searchable inbox paginates all imported messages, 30 at a time.
- Subject, sender, snippet and up to 50,000 characters of readable body text are cached for private search. Older metadata-only alerts are indexed in batches of 10 per sync or when opened. Search also includes internal notes. Filters cover sender, date range (India time), unread, starred, work status, files and sales links. Search covers imported email; it does not search the whole Gmail account.
- Opening a row fetches its Gmail conversation, including replies even when their subjects do not independently match the import filter. The reader loads the latest 20 messages and can load earlier messages. The latest page is privately cached for two minutes to reduce Google's full-thread request costs; Refresh bypasses that cache. A saved conversation can also be shown during a quota cooldown. Cache entries are scoped to the mailbox owner and removed on disconnect. Plain text is shown first; formatted content is sanitized, sandboxed and stripped of scripts, remote images and trackers. Large bodies are capped for dashboard display; the original remains available in Gmail.
- Files are fetched on demand through an authenticated route that verifies message ownership, conversation membership and MIME part identity. PDF, common images and text offer previews; all files can be downloaded. Files are streamed with private/no-store headers, are not persisted in dashboard storage, and are capped at 35 MiB. Use Gmail for larger files or unsupported previews. The existing Gmail read-only scope covers bodies and files.
- Local read, star, work status and internal notes do not change Gmail labels or send anything to the customer. Open the original using **Gmail** in the reader.
- Link a whole conversation to existing quotations/orders, or create a draft with sender details, an exact email-matched customer where available, and the email requirement. Review the customer, products, quantities, taxes, prices and terms yourself before finalizing. Repeated creation clicks reuse an existing linked draft of the same type. Finalized records are never silently reopened as drafts. Linked customer emails appear on document detail and edit pages for the mailbox owner. Unlinking does not delete the sales document.
- A PDF attachment offers **Extract order items**. The PDF is sent to the configured AI reader only when clicked. Digital PDFs and clear scans are supported, up to 12 MB, 25 pages and 100 extracted rows. The review shows editable titles, descriptions, quantities, units, unit prices, SKU/type/HSN, PO number/date and buyer, plus source page/evidence and warnings. Missing quantities/prices stay blank. Selected rows require positive whole quantities, explicit unit prices, INR currency and a review confirmation before creating/filling a draft. Foreign-currency orders and fractional quantities require manual handling with the current order model. Taxes, commercial terms and the customer must be checked in the normal order editor.
- Extraction results are cached privately per message/file. A processing lease prevents duplicate AI reads from repeated clicks. Limits allow 30 new PDF readings per account per hour. Repeated application opens the same resulting order. An existing empty linked draft can be filled; a draft with existing items is preserved and a separate draft is created. Catalog links require one exact unambiguous SKU/type match among active variants; unmatched or conflicting rows remain custom items. Only a draft is filled; no order is finalized or sent automatically. The source Gmail conversation remains linked to the resulting order. Disconnect removes saved readings and conversation caches, while sales documents remain.
- Disconnect deletes the encrypted refresh token, cached email content, notes and conversation links. Quotations and orders remain. Switching to another mailbox clears the old mailbox data. Reconnecting the same mailbox preserves it. Disconnect does not revoke the Google grant, because this may share a client with site sign-in. The account owner can remove the site's access in Google Account → Security → Third-party connections.
- Revoked/expired credentials and permission failures display a reconnect message. Sync failures retain existing alerts and do not advance the checkpoint. Gmail is never used to send, modify, or delete messages.
- Tokens are encrypted with AES-256-GCM at rest. OAuth uses short-lived encrypted state bound to the signed-in user, an HttpOnly SameSite cookie, and PKCE. All server actions and OAuth routes enforce the existing dashboard allowlist, and all data queries are scoped to the signed-in user's ID.

## Validation

Run `node --import tsx --test scripts/gmail-integration.test.ts scripts/gmail-pdf-import.test.ts` and `pnpm exec tsc --noEmit`. Tests cover token encryption, OAuth state binding, search windows, paginated full-text imports, nested MIME/files, HTML sanitization, charset decoding, quota fallback, import batching, missing-price review, catalog matching and file limits. Against a migrated database with a connected mailbox, run `node --import tsx -r dotenv/config scripts/gmail-sales.integration.ts dotenv_config_path=.env.local` to check sales draft creation, PDF item application, exact catalog links, duplicate prevention and preservation of existing draft items inside a transaction that is always rolled back. Digital and image-only fixture PDFs were also checked with a live model request; model quality can vary, so the review step is required.

For live verification, receive a matching customer email, verify one bell alert, open its conversation and a file, search a distinctive body phrase, link it to a sales record and reopen its source email from that record. Confirm repeated fetches do not duplicate messages. Verify unauthenticated attachment requests redirect to login and unauthorized cron requests return 401. Check the next scheduled production cron run while the dashboard is closed. Do not disconnect a real mailbox merely to test deletion. The integration does not send a test email automatically.

## Catalog matching and suggestions

### Mail and catalog suggestions

Each saved alert offers **Link mail** and **Extract products**. Opening either control fetches the owner's email on demand and searches orders and quotations using the subject, sender email, customer/contact names and detected PO references. An attached PDF is read automatically when there is exactly one; with several PDFs, select one under Product suggestions. Extracted PDF text also contributes customer names and PO references to the link suggestions. Exact PO matches rank above sender-email and name matches. A manual customer-name/PO search is available when the automatic matches are insufficient. Choosing **Link mail** uses the existing conversation-link helper, including links between a quotation and its resulting order. Links are never created merely by showing a suggestion.

Product suggestions query active products and active variants. Current display names are shown, while historical names, SKUs, type numbers and ratings remain searchable. Shared type numbers can yield several alternatives; an explicit conflicting wattage excludes a variant. Select and copy catalog suggestions for review. This does not create orders or change their items. Text-bearing PDFs are read with `pdf-parse`, up to 30 pages and 50,000 characters. Scanned, protected or unreadable PDFs can be handled by pasting descriptions manually. No OCR is included. Requests resolve Gmail message IDs and credentials from the signed-in user's alert, require sales read access, and never persist extracted text. Linking separately requires sales write access. PDF parsing is limited to 15 requests per minute per user.

Run `node --test scripts/gmail-suggestions.test.cjs` for matching, catalog lookup, owner/permission enforcement, and real PDF text extraction coverage. The same tests are included in `test:gmail`.

The suggestion checks passed 15 regressions, including a generated text-bearing PDF and a PDF with no text layer. Browser checks used the actual suggestion components with synthetic action responses at desktop and mobile sizes: automatic PO/PDF suggestions, linking, manual search, product selection, copying and repeated-description deduplication passed with no browser errors. These checks did not access a live mailbox. The existing integrity suite also passed; an existing quotation-rendering test timed out during concurrent checks and passed when rerun on its own.


## Historical import fixes

The default filter includes Purchase Doc and Purchase Document subjects. Exact legacy defaults upgrade automatically; custom queries are preserved. Fetch mail explicitly rescans the selected date range. Local history remains paginated, and unread bell previews include older mail.
