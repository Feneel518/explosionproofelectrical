## Where approved changes belong

| Location | Planned update after approval |
| --- | --- |
| Product master (`Product.name`) | Approved product display names only, matched by stable product ID. |
| Variant master (`ProductVariant.variant`) | Approved variant display names only, matched by stable variant ID and expected parent product. |
| Products, selectors and public catalog | Refresh database-backed displays and invalidate affected cached pages. |
| Quotation and work-order copies | Preserve issued names/specifications through document snapshots before master renames. Some views currently read live product/variant names. |
| Existing SKUs, type numbers, product/variant IDs and serials | Preserve these unless a separate, specific change is approved. |
| Historical quotation/order/invoice line titles and draft contents | Do not mass-rewrite them. Existing drafts and documents retain their recorded wording unless explicitly reviewed. |
| Future product and variant entry | Add family-specific naming rules and consistent formatting only as separately approved application changes. |

Before applying an approved batch, refresh the live source and compare expected old values, check per-product unique variant names, and produce an old/new change log. Corrections to ratings, material, thread, dimensions, grouping or equivalence are separate from a display-name rename.
